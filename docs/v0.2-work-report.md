# Hasemi-Sevina-49 v0.2 work report

## 1. Executive summary

The v0.2 branch integrates the minimum TinyQV RV32EC CPU/QSPI dependency
closure with the unchanged Hasemi v0.1 risk accelerator. Firmware boots from
external QSPI flash, uses external QSPI PSRAM, and accesses the existing
Hasemi register bank through a byte-native MMIO bridge. Local and hosted RTL
regressions pass. The final physical-fit decision is withheld until the exact
v0.2 GDS workflow artifacts are complete.

The hosted GDS workflow for the implementation SHA, run `36259705455`, was
cancelled after nearly six hours of detailed routing, with no artifact;
downstream precheck and GLS were skipped. The job log reports 71,783.8464 µm²
mapped synthesis area, 80.379% placement utilization and 18,778 intermediate
route violations after 12 optimization iterations. There is no final DRC.

## 4. Architecture implemented

- TinyQV RV32EC serial CPU and shared flash/PSRAM QSPI controller;
- external QSPI flash for instruction/program data;
- external QSPI PSRAM A for writable data, optional PSRAM B reserved;
- byte-native Hasemi MMIO bridge with deterministic unsupported/unmapped
  behavior;
- external SPI register access retained with priority over CPU MMIO;
- one 10 MHz system clock, no PLL or generated core clock;
- no UART, I2C, PWM, crypto, generic SPI peripheral or custom ISA.

## 6. MMIO map

Hasemi occupies `0x0800_1000`-`0x0800_107F`; the low seven address bits map
directly to the v0.1 register offset. Only byte loads/stores access the bank.
Unsupported sizes and unmapped external reads return `0xFFFF_FFFF`; writes are
ignored. Successful byte reads are zero-extended.

## 7. QSPI pin map

`uio[0]` flash CS, `[1]` SD0, `[2]` SD1, `[3]` SCK, `[4]` SD2,
`[5]` SD3, `[6]` PSRAM A CS, and `[7]` PSRAM B CS/reserve. Reset forces
`uio_oe=0x00` and deterministic `uio_out=0xC1`.

## 14. Known limitations

- Behavioral flash/PSRAM arrays are testbench-only and are not synthesized.
- External hardware must prepare flash continuous-read and PSRAM QPI modes and
  present the latency code during reset, following the upstream boot contract.
- Hasemi MMIO is deliberately byte-only in v0.2.
- Interrupt inputs to TinyQV are tied low; Hasemi status is polled over MMIO.
- PSRAM B is reserved and not required by the verification firmware.
- testbench QSPI pin directions and pad-level tri-state contention are not yet
  checked phase-by-phase; integrated external-SPI/CPU-MMIO overlap is not
  asserted with a top-level scoreboard. These checks remain open.
- this continuation runtime lacks local Icarus/cocotb and ASIC synthesis/P&R
  tools; the cited RTL result comes from the immutable hosted test run, and
  the hosted physical job did not finish.
