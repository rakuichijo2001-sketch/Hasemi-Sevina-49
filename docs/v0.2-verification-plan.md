# Hasemi-Sevina-49 v0.2 verification plan

## Regression policy

The four v0.1 cocotb tests remain unchanged in intent and expected values. They
run against the integrated top at 10 MHz with the QSPI input model quiescent.
Any v0.1 failure is a regression, not a reason to update an expected value.

## Testbench-only memory model

The flash/PSRAM model is derived from the TT06 Apache-2.0
`test/sim_qspi.v`. It models flash continuous-read transactions and PSRAM QPI
read/write behavior. ROM/RAM arrays exist only in `test/`; they are not listed
in `info.yaml` and must never be synthesized into the ASIC.

The boot test image is a small, reviewable RV32E program represented as assembly
source plus a text hex image. It configures Hasemi using byte accesses, exercises
PSRAM A, commits a sample, reads status and loops. It is verification firmware,
not an on-chip ROM.

## Static/synthesis checks

- compile every listed source; no unresolved module or implicit net;
- no inferred latch, multiple driver or combinational loop;
- imported register file implementation and mux count reviewed explicitly;
- no inferred program/data memory in synthesized RTL;
- CPU/QSPI logic must not be optimized away;
- unsupported and unmapped access behavior must remain reachable;
- compare total, sequential, combinational and mux cells with v0.1;
- triage dead/removed logic and every flow warning.

## Physical/GLS checks

- 3x2 placement and detailed route converge without fake timing exceptions;
- report density/utilization and congestion evidence;
- setup/hold WNS/TNS at all flow-reported corners;
- max slew/cap/fanout and unconstrained/unannotated paths;
- DRC, LVS, antenna and all Tiny Tapeout prechecks;
- GLS reuses the functional suite where practical and must include reset,
  MMIO/QSPI output determinism and core Hasemi regression.

### Coverage limits to close before final sign-off

- `mmio_bridge_tb` directly checks unmapped and unsupported accesses,
  byte semantics, SPI priority/stall, and suppression of a pending CPU write
  during reset. The top-level cocotb suite resets during QSPI boot and verifies
  successful reboot.
- The end-to-end suite exercises QSPI boot and PSRAM reads/writes, but the
  testbench does not model pad-level tri-state contention or explicitly assert
  every QSPI phase's `uio_oe` direction. Add that check before claiming a
  contention-free pin integration.
- The bridge arbiter has an isolated simultaneous-request test and the
  top-level test performs external SPI reads while the CPU is booting. There is
  no explicit scoreboard assertion that an external SPI transaction overlaps
  a CPU MMIO access at the integrated top.

The exact-SHA GDS job was cancelled during detailed routing after nearly six
hours; its streamed log provides partial synthesis and placement metrics but
no final route, GDS, precheck or GLS artifact. See the synthesis and physical
reports. RTL PASS is not treated as physical FIT evidence.
