# Hasemi-Sevina-49 v0.2 memory map

## Global map

TinyQV uses 28-bit physical addresses. Documentation writes them as eight hex
digits with the upper nibble zero.

| Address range | Owner | Access | Notes |
|---|---|---|---|
| `0x0000_0000`-`0x00FF_FFFF` | external QSPI flash | R/X | program and constants; no flash writes |
| `0x0100_0000`-`0x017F_FFFF` | external QSPI PSRAM A | R/W | primary data memory |
| `0x0180_0000`-`0x01FF_FFFF` | external QSPI PSRAM B | R/W | optional/reserved second PSRAM |
| `0x0800_1000`-`0x0800_107F` | Hasemi register bank | byte R/W | offset equals the existing 7-bit SPI address |
| all other external-bus addresses | unmapped | deterministic | reads return `0xFFFF_FFFF`; writes are ignored |

The selected Hasemi base does not overlap the TinyQV TT06 memory windows or its
legacy peripheral block at `0x0800_0000`-`0x0800_0027`.

## Hasemi MMIO semantics

- Native access type: unsigned byte load/store (`LBU`/`SB`).
- `addr[6:0]` is passed unchanged to the existing register bank.
- Read values are zero-extended to 32 bits.
- 16-bit and 32-bit accesses complete but return `0xFFFF_FFFF` on reads and do
  not write. Firmware must not use `LH/LHU/LW/SH/SW` on this window.
- Read-only and unimplemented register behavior remains owned by
  `hs49_register_bank`; unimplemented in-window byte reads return `0x00`.
- An external SPI transaction has priority. CPU MMIO waits with `data_ready=0`
  until SPI chip select is inactive.
- There is no combinational path from register read data back to its read
  address; the address is selected solely from the current granted master.

## Register offsets

All v0.1 offsets in [`register-map.md`](register-map.md) remain unchanged. For
example:

| CPU address | Existing offset | Register |
|---|---:|---|
| `0x0800_1000` | `0x00` | `CHIP_ID` |
| `0x0800_1002` | `0x02` | `CONTROL` |
| `0x0800_100D` | `0x0D` | `COMMIT` |
| `0x0800_1010` | `0x10` | `RAIN_WATCH_L` |
| `0x0800_1030` | `0x30` | `RISK_SCORE` |
| `0x0800_1031` | `0x31` | `RISK_LEVEL` |
| `0x0800_1037` | `0x37` | `SAMPLE_SEQ` |

Multi-byte Hasemi quantities remain little-endian pairs of byte registers.
