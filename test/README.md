# Hasemi-Sevina-49 verification

The cocotb regression exercises the real Hasemi RTL rather than the Tiny Tapeout arithmetic template.

Coverage in `test.py`:

- SPI Mode-0 register read/write at 1 MHz with a 10 MHz system clock.
- 16-bit sensor sample loading and explicit sample commit.
- Configurable watch/critical thresholds and per-sensor weights.
- Persistence filtering before risk-state transitions.
- NORMAL -> WATCH -> CRITICAL behavior.
- IRQ generation/clear.
- Stale-sample fault using the external 1 Hz tick.

Additional v0.2 coverage in `test_v02.py` and `mmio_bridge_tb.v`:

- deterministic unmapped and unsupported-size MMIO behavior;
- external-SPI-priority register-bank arbitration;
- TinyQV reset and boot from a testbench-only QSPI flash model;
- CPU byte reads/writes of the existing Hasemi register bank;
- CPU threshold configuration and risk/event-status reads;
- PSRAM A byte write/read round-trip;
- reset during boot and successful restart;
- deterministic QSPI `uio_out`/`uio_oe` reset state.

`sim_qspi.v` is derived from the TT06 TinyQV Apache-2.0 behavioral model.
`firmware/hasemi_v02.hex` is generated by `firmware/make_image.py` from the
reviewable sequence documented in `firmware/hasemi_v02.S`. Neither the model nor
the firmware image appears in `info.yaml`; they are not synthesized into the
ASIC.

Run from `test/` in a Linux environment with Icarus Verilog and cocotb:

```sh
python3 -m venv .venv
. .venv/bin/activate
pip install -r requirements.txt
make
```

Regenerate the test image and run the bridge unit test with:

```sh
python3 firmware/make_image.py
make mmio-unit
```
